# 10 仮予算とAIを使う運営方針

**更新:** 2026-09-28
**状態:** 利用者が合意した運営方針と、実装に向けた設計案。サービス契約・有料化・外部へのデータ送信を実行する指示ではない。
**対応:** `04` のA1（費用・文書）、A2（安全）、A5（運営）、A6（検証）、`03` のSolo Alphaと少数公開。フェーズ順序・既存の安全条件は維持する。

## 1. 合意した方針

- コストと運営者の時間の両方を抑える。無料枠を中心に始め、実測して見直す。
- 開発中は月額0〜1,000円を目標、1,000円を見直しラインとする。
- 最初の外部利用者20人程度では月額1,000〜3,000円を目標、3,000円を見直しラインとする。
- 上の金額は仮予算であり、請求保証や自動的に止まる上限ではない。有料化・上限変更は理由と金額を示して利用者が判断する。
- Apple Developer年会費、ドメイン、開発用ChatGPT / Codex契約は別枠。AI運営APIの有料処理はサービス利用料に含める。
- AIが一次判定・分類・重複整理・要約を補助し、人が重大な処分を判断する。
- 毎日10〜15分で確認待ちを確認できる運営を設計目標とする。実際に確認できる時間帯・所要時間は未確認であり、公開前に確かめる。
- 募集は最初20人を上限として準備し、費用と確認待ち件数を観測して拡大を判断する。DM・動画・広告・課金は既存計画どおり初期OFF。

## 2. 料金調査の基準

2026-09-28に公式料金を確認した参考値。実装・契約直前に再確認する。

| サービス | 開始時の候補 | 有料の参考値 |
| --- | --- | --- |
| Workers | Free。必要機能・CPU上限内で使えるか確認 | Paidは月額$5から。超過分は別途 |
| Turso | Free。保存・読み書き・復旧条件を確認 | Developerは月額$5.99、超過設定は別途 |
| R2 Standard | 保存10GB/月等の無料枠。写真を端末で圧縮 | 保存$0.015/GB月、操作別課金。転送料は無料 |
| Expo EAS | Freeのビルド・更新配信枠 | Starterは月額$19と追加使用料 |
| AI一次判定 | OpenAI Moderation APIを候補として評価 | Moderation endpointは無料。要約等の生成モデル料金は別 |

出典: [Workers](https://developers.cloudflare.com/workers/platform/pricing/)、[R2](https://developers.cloudflare.com/r2/pricing/)、[Turso](https://turso.tech/pricing?frequency=monthly)、[Expo](https://expo.dev/pricing)、[Moderation](https://developers.openai.com/api/docs/guides/moderation)。

登録者数だけで費用を推定しない。月次のAPI回数・CPU、DB読み書き、写真の累積容量・操作数、ビルドとOTA、AI呼出回数・トークン、バックアップ・監視費用を計測する。為替・税・複数環境の使用量を含めて月末予測を作る。

予算超過防止の設計案: 仮予算の70%で内訳確認、90%で募集と高費用機能の開放を止める。通知は請求の停止ではない。レート制限、写真サイズ・枚数制限、キャッシュ、AI呼出上限・再試行上限、各サービスの超過課金設定を別に確認する。費用上限に達しても通報・削除受付を先に止めない。

## 3. AIと人の分担

| AI・自動処理の担当 | 人の担当 |
| --- | --- |
| 本文・画像の一次判定、スパム・連投検出 | 文脈依存の違反判断と保留解除 |
| 通報の分類、同一対象の重複整理、優先度候補 | 重大通報の初回確認・対応 |
| 必要な判断材料の要約と原文への参照 | 永久停止、異議申し立て、深刻な未成年被害への対応 |
| 検証済みの条件による一時保留 | 最終処分と監査理由の記録 |

AIの要約は証拠の原文を置き換えない。モデルの分類は本サービスの規約違反の確定ではない。通報件数だけで自動BANしない。推薦システムは `01` 第6章どおりLLM / 外部AI APIを使わず、今回のAI利用は安全運営に限定する。

## 4. 実装フローの設計案

1. 投稿・編集・写真追加の各バージョンを、IDと内容バージョンで識別する。
2. レート制限等のルールと一次判定を実行する。判定は同じ内容について再利用し、重複呼出を抑える。
3. 通報は判定結果にかかわらず受け付ける。AIが安全とした投稿も通報・人の確認対象になれる。
4. 確認キューに種別、優先度候補、原文参照、根拠、検出時刻、判定モデル・ルールの版を記録する。内容編集後に古い判定で公開しない。
5. 評価済みの高リスク条件は一時保留へ送る。永久停止・不可逆削除はAIだけで実行しない。利用者に状態と異議申し立て導線を示す。
6. 管理者が原文と文脈を見て判断し、理由と実行結果を監査記録に残す。

最初は隔離したテストデータで評価し、次に処分へ影響させない比較運転を行う。その後、検証できた条件だけ一時保留を有効化する。投稿公開前の判定待ち・障害中の挙動は評価時に決め、未判定を「安全」と記録しない。外部AIの障害時は再試行を制限し、保留と管理者通知へ回す。確認待ちが処理能力を超えたら新規募集を止め、必要なら新規投稿等を制限する。

## 5. 外部AIへのデータ送信条件

- providerは未決定。無料のAPIを候補にするが、APIキーの取得や実ユーザーの送信はまだ行わない。
- 公開前にproviderの保存期間・学習利用・削除・送信先・契約条件を確認し、プライバシー文書へ記載する。適合を確認できなければ実データを送信しない。
- 生年月日、メール、認証情報、アカウントの全履歴は送らない。必要な投稿・通報の範囲に絞る。一般的な要約には不要な個人識別情報を除く。
- 投稿・画像・通報文は信頼しない入力として扱う。文章内の指示を実行しない。AIには処分APIやDB更新の権限を持たせず、出力を構造検証する。
- 既知・疑いのある児童性的虐待画像をOpenAI Moderation APIへ送らない。同APIは専用の検出・対応手段ではない。この種の画像の遮断・証拠アクセス・通報経路は別途設計し、一般AIへの送信で代替しない。
- DMは初期OFF。将来DMを開放する際のAI送信範囲は別途決め、今回の方針から全DMの外部送信を推定しない。
- AIの判定・要約・証拠も保持と削除の対象。`07` の保持方針が確定するまで無期限保存にしない。

## 6. 公開前の確認条件

- 通常の陸上写真、強い練習表現、冗談・引用、嫌がらせ・脅迫・個人情報暴露・スパムを含む日本語の評価例で、見逃しと誤判定を別に測る。
- 同一内容への重複処理、編集後の再判定、APIタイムアウト、再試行切れ、予算到達、AIの不正出力を確認する。
- 通報から人の確認までが追跡でき、既存の重大通報24時間以内の初回確認条件を満たせることを確認する。AI通知だけで確認済みにしない。
- 保留・異議申し立て・管理者操作の権限と監査を確認する。
- 人の確認待ち件数、最古の重大未確認時間、処理時間、誤保留の解除率、AI呼出費用を測る。
- 人が確認できない予定に備え、募集停止と投稿等の制限手順を用意する。具体的な時間帯と連絡経路は公開前に確定する。

## 7. 未確定事項と開発への引き渡し

未確定: 実際の確認時間帯、providerと契約・データ処理条件、生成モデルと料金、判定閾値、画像の専用安全対策、障害時の公開制御、保持期間、正式文書。以前提案した証拠90日・監査1年・削除7日等は今回の合意で確定していない。`07` は引き続き設計案。

開発側はまず既存の安全API・管理者権限・監査に対してこの案を照合し、必要なキュー・判定状態・flagと評価手順を計画する。外部AIをつなぐ前に隔離データとstubで経路を検証できる設計にする。既存の開発作業が完了した区切りで `04`・`05` にこの資料への参照と実装状況を反映する。仮予算とAI方針の合意を、実装や公開の完了と扱わない。
