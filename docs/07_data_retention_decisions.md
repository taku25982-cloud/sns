# 削除・調査記録の保持方針（公開前の決定事項）

**状態:** 設計案。利用規約・プライバシーポリシーの確定文面ではない。
**根拠:** `01_product_requirements_and_architecture.md` 5.6、`02_ui_screen_spec.md` SET-001、`03_cold_start_rollout_operations.md` Solo Alpha。

| データ | 削除申請直後 | 30日の取消期限後 | 公開前に決めること |
| --- | --- | --- | --- |
| プロフィール・投稿・写真 | 他ユーザーの画面とAPI取得から除外 | 本人情報とmediaの削除を開始 | 非同期削除の再試行・完了確認、配信キャッシュの失効 |
| 認証情報・セッション | 取消用の本人確認経路だけ維持 | 認証情報とセッションを削除 | 取消時の本人確認、削除完了までの上限時間 |
| フォロー・ブロック・保存などの関係 | 表示・操作に使わない | 個人に結び付く関係を削除 | 削除ジョブの順序と失敗時の再試行 |
| DM | 本人の一覧から除外 | 相手側に残す表示を仕様に合わせて整理 | 相手側に残る本文・差出人表示と取消操作の範囲 |
| 通報・異議申し立ての証拠 | 一般表示から分離し管理者だけが閲覧 | 調査に必要な最小限だけ保持し、期限後に削除・匿名化 | 保持対象、保持期間、未解決案件の扱い、本人への説明 |
| 管理者の監査ログ | 管理者だけが閲覧 | 調査に必要な範囲だけ保持 | 保持期間、識別子の匿名化時期、アクセス記録 |
| バックアップ・分析・キャッシュ | 公開表示を停止 | 復元・集計から再表示されないよう処理 | バックアップの保存期間、復元時の削除再適用、外部サービスでの削除確認 |

## 現在の実装と公開条件

- APIは削除申請・30日以内の取消を実装し、申請時に `deletion_pending` として本人プロフィールと他者の取得対象から除外する。削除受付flagは初期OFF。
- 最終削除・匿名化ジョブ、media・DM・バックアップ・分析の処理は未実装。上表の決定と検証が済むまでflagをONにしない。
- 公開前に保持期間と例外を本人向けの文書に明記し、申請・取消・削除完了を一人で検証する。
